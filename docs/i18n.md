# Translations

Every user-facing string is translatable. There are no shipped translations
yet; this documents how the strings are wrapped and how to add a language.

## How strings are wrapped

Plasma injects KDE's `i18n()`/`i18np()` into applet QML through
`KLocalizedContext`, bound to this widget's domain
(`plasma_applet_io.github.schiz0x00.kclaude`). Files that only ever run
inside plasmashell call `i18n()` directly:

- `contents/ui/main.qml`
- `contents/ui/FullRepresentation.qml`

Three files also run where `KLocalizedContext` does not exist, and use a
guarded wrapper that falls back to identity (with `%1` substitution) when
`i18n` is not on the scope chain:

| File | Wrapper | Why it cannot call `i18n()` bare |
| --- | --- | --- |
| `contents/code/TimeUtils.js` | `_tr()` / `_trp()` | loaded by `tst_timeutils.qml` under qmltestrunner |
| `contents/ui/configGeneral.qml` | `page._tr()` | loaded by `tst_config.qml`; a bare `i18n()` is a ReferenceError there and every label renders blank |
| `contents/code/FileUsageProvider.qml` | `root._tr()` | `tst_provider.qml` drives `_parseResponse()`, and a ReferenceError inside its try/catch would masquerade as a parse error |

In production the wrappers delegate to the real `i18n`, so translations apply
everywhere. Under test harnesses they return English, which is also what the
tests assert against.

Deliberately not translated: the product names ("kclaude", "Claude"),
commands and paths (passed as `%1` arguments so translators never touch
them), unit suffixes in spinboxes (" s", " %"), and strings that arrive as
data — window names from the usage file and the collector's `error` message
(the daemon writes English; it is machine-generated data, not UI chrome).

## Extracting the template

```bash
xgettext --from-code=UTF-8 -L JavaScript \
    -ki18n:1 -ki18nc:1c,2 -ki18np:1,2 -ki18ncp:1c,2,3 \
    -k_tr:1 -k_trp:1,2 \
    -o plasma_applet_io.github.schiz0x00.kclaude.pot \
    contents/ui/*.qml contents/code/*.qml contents/code/*.js
```

The `-k_tr:1 -k_trp:1,2` keywords pick up the guarded wrappers; everything
else is the standard KDE keyword set.

## Adding a language

```bash
msginit -i plasma_applet_io.github.schiz0x00.kclaude.pot -l de --no-translator
# translate de.po, then:
mkdir -p contents/locale/de/LC_MESSAGES
msgfmt de.po -o contents/locale/de/LC_MESSAGES/plasma_applet_io.github.schiz0x00.kclaude.mo
```

`kpackagetool6` installs `contents/locale/` with the rest of the package, and
KDE's locale machinery picks the catalog up by domain name. Reinstall
(`./scripts/install.sh`) and restart plasmashell to see it.

## When adding new strings

- New text in the two plasmashell-only QML files: plain `i18n("...")`.
- New text in the three guarded files: use the file's existing `_tr()`.
- Text in a *new* file: use `i18n()` unless a test loads that file under
  qmltestrunner — then copy the guarded pattern and add the keyword note
  here.
- Never concatenate translated fragments; use `%1` placeholders so word order
  can change per language. Keep commands/paths as arguments.
